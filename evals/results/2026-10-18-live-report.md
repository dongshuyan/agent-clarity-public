# 实际 CLI 对照与最终验收

最终规则已在新 Codex 会话中加载并使用。三项新任务的六份输出均通过准确性与可用性检查；新增规则侧保留了影响理解和操作的条件，并按任务省去无关维护细节。三组与原有基线均持平。这支持本项目作为可用的定制规则交付，不能证明它在所有任务中都比原有模型更好。

## 运行方式

使用本机 Codex `0.163.0-alpha.10.2` 的 app-server 协议，通过当前桌面账户已有的认证桥接调用模型。启动响应逐次核对 `gpt-6-astra`、`high`。没有改全局提示词、模型或认证配置。

每一侧使用一个新建的临时会话、独立 Git 根目录、相同任务与原材料。基线保留现有全局指令和能力；规则侧只加入本项目表达规则及 Skill，没有加入标题功能。启动响应列出的指令来源与这一区分相符。

每个条件每批生成一次，没有反复抽样挑选答案。实际输出、基线和不利结果都保留。原始日志只在 `.local/`；仓库中的 JSON 删除了账户路径和会话标识。写作提示只给任务与原材料，未包含核对答案。工具日志显示的是规则查找、读取，没有读取另一侧输出、核对题或匿名映射。第二轮基线开发组还按已有全局规则读了 humanizer；这代表本机真实基线，并非“没有任何写作指导”的弱基线。

评审另开不继承历史的 Agent 会话，平台配置为 `gpt-6-astra`、`xhigh`。逐题随机交换 A/B，评审不知道方法标签；先对照完整材料核对信息，再检查读者问题、结构和表达。主 Agent 阅读全部输出并核对具体问题。

第二轮包含 GPT with Taste 固定版本的公开安装记录、复杂切换流程、首轮人工复核歧义回归，以及三个保留任务。

| 任务 | 偏好 | 原因 |
| --- | --- | --- |
| 公开上手案例 | 基线 | 新规则侧保留了过多维护和审计细节，提醒现状放得较晚 |
| 复杂切换流程 | 新规则 | 把共同前提和两个条件分支放在一起，减少跨步骤拼接 |
| 方案比较回归 | 持平 | 两侧准确，新增规则侧没有再把“都需复核”扩大为“工作量相同” |

12 份输出均准确可用；偏好计数为新增规则 2、基线 1、持平 3。此为单次定性判断，没有统计意义。原文、匿名评审和映射见 [第二轮结果](2026-10-18-live-v2.json)，当时规则见 [规则正文快照](rules-v2/project-expression.md)。

根据上手案例的问题，最终规则明确：完整性取决于读者任务，不是逐条复制原始记录；实现字段、测试计数和开发计划仅在影响当前理解或操作时进入正文。同时加入一个独立编写的信息取舍示例，要求将安装或调查记录改成使用说明时参考。没有据此改写旧输出来美化结果。

## 最终版本的新材料检查

规则改动完成后，准备三项新假设任务：Maple 上手及恢复说明、订单超时后能否重提、带容量和时间约束的服务选择。新任务没有加入 Skill 示例；输出后也未再调整规则。

| 任务 | 新规则侧检查 | 相对基线 |
| --- | --- | --- |
| Maple 上手与恢复 | 保留开始方法、备份未启用且未真实验证、首次成功确认、恢复凭据和顺序；省去内部字段与审计计数 | 持平 |
| 超时与重复提交 | 解释读取和写入差异，保留“查询不到不等于未创建”及保护尚未实现 | 持平 |
| 服务选择 | 选择满足容量、时限与预算的 C，没有因 D 即时就忽略其容量不足；人工工作量仍未知 | 持平 |

六份输出均可用。基线的一处首句将条件性人工检查要求写得稍宽，正文已正确限定；评审列为轻微问题，没有将它算作实质错误或据此强判优胜。全文、评审及映射见 [最终结果](2026-10-18-live-v3.json)。便于直接阅读的例子见 [效果示例](../../docs/examples.md)。

## 结论的范围

最终版本通过本轮“事实和重要条件正确、任务可完成、文字可直接使用”的小样本检查。没有测量真人阅读时间、理解率或个人偏好，不能宣称达到某个百分制分数，也不能保证每个回答都改善。

当前基线本身已有较强写作规则，新增 Skill 的价值是把本人的表达要求固化为可复用、局部生效的约束。测试没有证明通用增益；对高风险内容仍需事实核对。这里保留这一结论，不通过削弱基线或挑选输出制造胜率。
