# 首版表达检查

这批输出没有显示新增规则带来稳定优势。8 组比较中，基线和新增规则各有 1 组被偏好，6 组持平。规则已经能作为项目内试用版本交付，但不能据此声称理解效率提高，或已经达到某个百分制水平。

## 实际做了什么

原计划的本机 Codex CLI 对照在第一次写作请求时遇到认证错误，未产出文本。随后创建两个不带当前对话历史的独立 Agent 会话，平台参数均指定为 `gpt-6-astra`、`high`。两侧收到相同的 8 项任务和材料；一侧使用已有指令，另一侧额外收到项目的表达规则、Skill 和示例。标题规则未加入。

材料全部是本项目准备的假设情境，覆盖上手文档、概念解释、方案比较、进度报告、操作说明、英文论文段落、简单句保留及证据范围。写作输入不含核对答案。两个会话各批量生成一次，没有重复抽样或根据输出调整本轮规则。

第三个独立会话按 `gpt-6-astra`、`xhigh` 配置评审。每个任务随机交换 A/B 顺序，评审输入没有指明哪一侧用了规则。评审先核对完整原始材料，再检查理解问题和表达质量。主 Agent 随后阅读两侧全文，并复核评审指出的具体问题。

## 结果

| 任务 | 比较结果 | 具体观察 |
| --- | --- | --- |
| 新人上手 | 持平 | 都能从当前可做的事出发，并区分已验证和未生效的功能 |
| 缓存解释 | 持平 | 基线的库存数字例子有助理解；新增规则侧更明确排除了“修改后固定等 60 秒”的误解 |
| 方案比较 | 基线较好 | 新增规则侧说“不会减少这项复核工作”，可能把仍需复核扩大为工作量不减 |
| 修复进度 | 持平 | 都保留了失败测试、未做浏览器验证、未部署和未确定根因 |
| 导入说明 | 持平 | 都保留了重复 ID、覆盖、预览和备份条件，并按步骤安排 |
| 英文论文段落 | 新增规则较好 | 更完整保留未开展因果实验，以及标准差不是置信区间的说明；优势有限 |
| 已清楚的短句 | 持平 | 都原样保留，没有强行扩写 |
| 演练与切换条件 | 持平 | 都没有把抽样通过扩展为生产切换已经可行 |

基线 8 份的主要信息保真检查均通过；新增规则侧 7 份通过，方案比较的 1 份因歧义记为 `uncertain`。这不是已确定的数值错误：若“不会减少”仅指仍需复核，含义可以成立；若读者理解为工作量不可能降低，则超出了材料。合适的表达是“选择 B 仍需要人工复核异常记录”，不额外判断工作量。

评审认为两侧文字均足以回答预设理解问题；这是模型对文字的判断，不是真人阅读测试。基线论文段落省略了“没有做因果实验”的方法事实，但仍准确保留不能据此得出因果解释的结论边界，因此没有按关键错误判失败。

## 如何使用这个结果

保留首版作为局部试用，不推广为全局默认，也不继续堆叠写作禁令来追求评分。现有运行环境的基线已经较清楚；当前数据支持的是“规则可以表达并复用这套要求”，尚不足以支持“增加它就会明显更好”。

方案比较中的歧义要作为回归案例保留。后续若修改规则，应另准备新任务验证，不能把这批已看过的任务继续称为未见测试。本轮不修改原始输出来掩盖问题。

## 限制与可核对材料

- 这是独立 Agent 的规则行为检查，不是失败的 CLI 配置对照，更不是桌面全流程验收。
- 两侧各一个会话、每个任务一份输出，不能估计稳定性或统计显著性；评审也是模型判断。
- 任务构造和主复核来自同一项目作者。匿名评审减少了标签影响，但不能消除共同模型偏好。
- 输入没有注入核对答案，但没有建立文件系统级读取隔离，也没有独立审计全部子会话工具日志。
- 论文材料用“accuracy ± 三次运行标准差”的常见记法，没有明确中心值的计算方法。两份都按均值解释；下一版材料应明确这一点，不能把本轮结果当作已验证该计算。
- 没有真人阅读时间、回读次数或操作结果数据，不报告效率提升比例。
