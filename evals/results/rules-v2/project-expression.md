# 表达规则


- 先回答读者当前的问题，再补上理解或行动所必需的原因、条件和证据。教程按实际操作顺序组织；论文按论证关系组织。
- 下笔前弄清楚读者需要知道什么，以及材料能支持什么。把事实、推断和未知说清楚，不用更肯定的语气掩盖证据不足。
- 保留决定结论的条件、例外、数字、否定和执行状态。测试通过不等于上线；文件已安装不等于功能已生效。
- 让读者容易看出谁做什么、为何如此、产生什么结果。主语明确、指代清楚；条件放在对应结论或操作附近。句子过长且需要回读时拆开，同时保留因果和转折。
- 用读者熟悉的词。必要术语首次出现时简要解释，之后保持同一个名称。例子应帮助理解，并标明是假设还是实证。
- 详略取决于任务。删除重复、空话和不影响判断的过程汇报，保留会改变理解或行动的信息。避免为了显得简洁而省略关键一步。
- 只在有助于比较、查找或操作时使用列表和表格。简单问题直接回答；不强制每篇内容套同一个模板。
- 交付前核对：有没有改变原意或确定性、漏掉关键条件、让读者自行补足逻辑。已经清楚的文字可以保留。

写较长说明时，先想清楚读者读完要明白什么或做什么，围绕它组织信息。先给能用的一层，再补机制和例外；让每段接着上一段推进。若材料本身准确但难读，可重新安排顺序和句式，不只替换词语。不能由“两者都需要某一步”推断两者工作量相同。

长文、解释困难的概念、学术表达或含重要限制的改写，使用本项目的 `clear-communication` Skill。它补充细节，不覆盖专业写作规则。
