# 表达评估

当前版本的规则已经通过真实 Codex app-server 会话加载和写作检查。最终三项新任务中，两侧共六份输出均准确可用，三组持平；此前六组对照中，新规则 2 组更清楚、基线 1 组更清楚、3 组持平。这里没有把可用性检查说成普遍优于原模型。

完整结果见 [实际 CLI 对照与最终验收](results/2026-10-18-live-report.md)，直接看文字可用 [效果示例](../docs/examples.md)。

## 判断什么

先核对原材料中的事实、数字、条件、否定、证据强度、执行状态和重要操作步骤，再看读者能否找到答案、理解关系并正确行动。保真不等于原材料每一条都进入正文；是否遗漏取决于当前读者任务。不能通过删掉重要限制让文字显得简洁，也不能以字数短或“更像人”代替准确性。

两侧使用相同模型、档位、任务及原材料，分别新开会话。基线使用当前环境已有规则；另一侧只加入本项目表达部分和 Skill。每个条件每批生成一次，不挑选输出。匿名评审不知道规则标签，允许持平；主 Agent 随后核对全文和具体判断。

阅读问题只能覆盖部分信息，所以同时对照完整来源。字符数、模型评分和偏好都不能当成真人阅读速度。`read-only` 也不是读取隔离；本次另外检查了实际工具访问记录。

## 材料与版本

- `cases.json`：最初八项假设任务；历史结果保留，不再作为未见任务。
- `cases-v2.json`：六项任务，包含一个有固定版本与 MIT 许可的 GPT with Taste 原始公开案例。
- `cases-v3.json`：最后调整后准备的三项新假设任务，未用于继续修改该轮规则。
- `results/`：实际输出、匿名评审、标签映射、规则版本信息与结论。

## 复现

```sh
python3 evals/run.py --cases evals/cases-v3.json --split holdout --run-name my-check
```

默认只准备独立工作目录和输入，不调用模型。加 `--execute` 才执行，消耗当前账户配额；已有运行目录不会覆盖。默认使用 `gpt-6-astra` / `high` 和 `app-server` 传输，优先沿用 `CODEX_CLI_PATH`；普通 CLI 登录环境也可选择 `--transport exec`。

本次使用的默认 app-server 路径会核对启动响应中的实际模型与档位，并要求明确的 `final_answer` 和成功结束的回合；过程消息、未知阶段、超时和失败不能算完成。取消等待会尽力中断模型回合。可选 `exec` 路径只检查退出码和输出 JSON 结构，没有这些协议层核验，也不将其结果视为同等证据。各运行的原始日志、命令与本机路径只保存在忽略的 `.local/evals/`。
