# 三段式标题插件

标题格式为 `状态｜初始需求｜当前进展`。插件中的 Skill 让 Agent 理解任务并选择内容，Python 脚本检查作用范围，通过 Codex API 真正改名并回读确认。插件没有替换 Codex 自身的标题生成算法。

## 三段分别表达什么

- **状态**：讨论中、调研中、方案中、实现中、验证中、待确认、待验证、已完成、已暂停、受阻。回答结束不等于任务完成；仍需验收时不能写“已完成”。
- **初始需求**：用户最初要解决的问题。首次成功设置后保持稳定。
- **当前进展**：正在做的具体工作，或已经完成的结果。应提供状态之外的信息，例如“检查手动改名保护”。

两个新生成的描述段各为 1–28 个字符，建议 6–18 个中文字符，不含分隔符、换行或控制字符。旧版本已固定的初始需求最多 48 字符，升级时保留，避免丢失原名称。

## 会话切换评分前缀（0.7.0）

会话更换评估结果采用机器管理的可选前缀，原三段语义标题保持不变：

- 有效评分：`S2·68分｜讨论中｜初始需求｜当前进展`
- 数据不足：`未评分｜讨论中｜初始需求｜当前进展`
- 评分关闭：保留原来的 `状态｜初始需求｜当前进展`

`S1` 到 `S4` 只表示评估档位；分数是未校准的 0–100 建议分，不是概率。原因、覆盖率和未知项不塞进标题，留给评估详情或 Hook 提示。评分前缀保存在独立的 `.local/title-scores/` 状态中，不进入三段标题保护记录。

用户修改三段语义标题时，原有分段保护继续生效。用户直接修改评分前缀时，评分前缀自动更新会暂停，并保留用户写入的内容；三段标题仍可继续维护。评分写入和普通标题写入共用会话锁，重读当前值后仅替换前缀，并回读确认。S1/S2 由 `session_score.py` 的确定性规则计算，默认 S2，新增监控模型调用为 0。S3/S4 只在周期或 S2 阈值探测回合要求当前任务模型提交一次受限标签；程序计算有上限的语义增量，模型没有额外请求。提交失败、未知或超时显示 `未评分`，不回退到 S2；非探测回合显示 S2。S4 的有限历史包括最近三轮用户/助手最终内容、标题状态与进展、以及白名单工具状态；明确决定仍须出现在这些最终内容中，插件不额外生成决定摘要。原生 Hook 缺少实际窗口上限时，按已确认的选择使用模型目录中的参考窗口，保留来源；未知模型或无效数据仍未评分。Codex `0.167.0-alpha.3.2` 的 CLI 新建、续聊和标题持久化已验证，桌面侧栏和警告渲染尚未视觉验收。安装与档位用法见[评分使用说明](session-monitor.md)。`title_runtime.py set-score` 保留为适配器和注入测试入口。

本地适配器调用示例：

```sh
python3 "/插件实际安装路径/scripts/title_runtime.py" --global set-score \
  --level S2 --score-status scored --score 68
```

没有评分数据时使用 `--score-status insufficient_data`；关闭评分使用 `--score-status disabled`。这两个状态都不要求提供 `--score`。

## 安装范围

入口为 `python3 scripts/title_plugin.py install --global`，或 `install --project /absolute/git/root`。两项互斥。全局指当前 `CODEX_HOME`，不是本机所有 Codex 账户；项目模式的目标须为独立 Git 根目录，并已通过 Codex 的项目信任流程。安装器不替用户写信任记录。

0.5.0 增加显式的 `install --global --portable`。0.6.0 加入 S1/S2 零模型评分观察 Hook；0.7.0 在同一入口加入 S3/S4 受限同回合自检和隔离的 S4 历史。安装前需要重新审查新版 Hooks；共享状态位置仍由包内 `global-installation.json` 固定。其他 Codex home 可配置同一个本地插件市场并审查新版 Hooks；继承该配置的 Harbor 窗口会使用同一份状态，不要求每个账户复制 `.local/`。共享目录应放在内部磁盘，不能指向会被退出登录或临时实例清理的目录。普通全局安装继续按账户隔离。

共享安装中的标题保护记录、S1/S2 数字读数和受限标签结果仍位于共享状态根，便于切换账户后继续看到同一会话的机器状态；S4 的用户/助手原文摘录另按当前 `CODEX_HOME` 分目录保存，避免跨账户泄露文本。

共享安装迁移时，须保留已有 `.local/titles/` 保护记录，并停用各 home 中旧的标题插件，避免两套 Hooks 同时执行。同一共享包的缓存可位于不同账户目录；运行前核对整个包与安装记录的摘要。修改过的副本不参与全局检查。新增的独立 Codex home 仍需加载插件配置；Harbor 从已配置的历史位置创建新账户/窗口时可沿用其原有继承机制，不需要复制登录信息。

项目模式把插件复制到目标的 `.local/agent-clarity/marketplace/`，在项目 `.codex/config.toml` 配置来源与启用项，并在 `AGENTS.md` 追加托管规则。全局模式使用 `CODEX_HOME/agent-clarity/` 作为独立存储根，在 `CODEX_HOME/config.toml` 与全局规则文件中配置；有非空 `AGENTS.override.md` 时使用它，否则使用 `AGENTS.md`。后续操作依照安装记录找到原来的规则文件，防止卸载遗漏。

Codex 负责将插件装入正式缓存。安装器核对插件 Skill、路径和文件摘要，并用 `hooks/list` 检查新版六类事件中的七项命令是否启用和受信任。全部满足才返回 `installed` 或 `updated`；尚未信任时返回 `needs_hook_review`（退出码 2），其他未就绪状态返回 `runtime_not_ready`。安装发现只查询本地插件目录，不等待远端插件市场。

每个项目的插件市场标识由项目绝对路径派生。两个项目分别安装时，更新或卸载一个项目不会清理另一个项目的缓存。项目移动后应重新检查安装记录；不要直接搬用含绝对路径的 `.local/`。

- 全局模式覆盖任意现有目录的新会话与继续对话的旧会话，支持非 Git 目录和用户分叉。只维护当前会话，不批量扫描改名历史会话。
- 项目模式只管理启用后新建的本项目根会话。更新保持原启用时间；卸载后重新安装会重置时间，停用期间的会话也不会被接管。
- CLI 入口只从 `CODEX_THREAD_ID` 读取当前会话，不接受任意会话 ID。
- 全局模式核对调用目录与目标会话目录一致；项目模式要求两者都属于目标 Git 根，并排除 `reference/`、`.local/`、嵌套 Git 仓库与分叉。
- 两种模式均不接管内部子代理。
- 使用插件内的 `UserPromptSubmit` 和 `Stop` Hooks；须在同一账户的 Codex CLI `/hooks` 中审查并信任。安装器不改信任记录、不关闭审查。升级时只移除与早期生成结果完全一致的旧项目 Hooks，并留下备份；有用户修改时停止迁移。

表达 Skill 独立保留；安装或卸载标题插件不改变它。

## 全局与项目安装的交接

0.4.0 中全局优先。项目脚本发现全局已启用时停止写入；即使两个插件都加载，也只有与全局安装记录路径匹配的缓存脚本执行全局检查。账户协调锁将启用、停用和正在进行的标题写入串行化，防止范围切换后收到旧操作覆盖。

同一会话的保护记录使用递增的 `revision` 判断先后。全局接管时读取已有项目保护；卸载全局后，项目版继续时读取更新的全局记录。因此全局的自动改名不会被项目版误当成用户手改。旧记录没有 `revision` 时按 0 处理，原格式和保护信息保留。

`install --global --migrate-project /absolute/git/root` 可显式清理旧项目包：全局就绪后复制保护记录、保留更高版本记录，再卸载项目版。同版本但内容不同的冲突会停止迁移；不会把全局的新状态覆盖为旧项目状态。迁移在账户锁内重新确认全局仍启用，若已卸载则保留项目版。

0.3.x 缓存没有上述协调逻辑，须迁移卸载或升级，不能据 0.4.0 的测试声称它可以直接共存。

## 简短问答与漏做检查

0.2.0 只靠模型主动遵循项目规则，实际出现了已加载插件但直接回答、完全未调用改名脚本的情况。0.3.0 增加两步：

1. `UserPromptSubmit` 记录当前回合标识，并提醒：即使是简短问答，也须在最终回复前核对一次标题。名称无变化时只记录核对，不重复改名。
2. `Stop` 检查本轮是否成功核对。漏做时返回一次 `decision: block`，让 Agent 补做标题维护。补做后不再触发第二次；已经处于补做流程、保护暂停、写入结果待确认或检查出错时，都允许回答结束。

Hooks 不替用户命名，也不在脚本中猜测任务状态。标题内容仍由 Agent 生成，通过现有管理器写入。回合记录位于安装存储根的 `.local/title-turns/`；成功核对绑定调用开始时的回合 ID，旧回合延迟完成不能代替新回合核对。检查和卸载共用协调锁及安装锁，卸载完成后不再要求补做。

这是有次数上限的补救，不保证所有模型都会遵循补做指令；需要结合真实回合确认。补做会额外运行一小段，指令要求保留原回答、不把改名过程加入正文；本次故障注入联测没有重复正文。未通过 Hooks 信任审查时，这两步都不会运行。

## 手动改名与写入保护

借鉴并复用上游的分段保护：用户手动修改状态、初始需求或进展后，修改过的段保持原样，其他段继续更新。用户的自定义状态也会被保留，不强行改回状态词表。

接管后观察到无法解析为三段的外部名称，会整体暂停覆盖。首次接管没有保护记录的普通标题时，会替换为约定格式；已有三段式标题则保留中间的初始需求。脚本不能识别未记录的历史名称是否曾手动修改。希望保留某个名称，可在接管后修改，或卸载标题插件。

| 返回值 | 含义 |
| --- | --- |
| `updated` | 写入后已回读到目标名称 |
| `unchanged` | 已是目标名称，无须重复写入 |
| `disabled` | 该范围未启用、已卸载，或已被全局接管 |
| `out_of_scope` | 会话早于启用时间，未接管 |
| `paused` | 外部名称无法安全合并，保留标题 |
| `pending` | 上次写入结果尚不确定，暂不重发 |
| `error` | 范围、状态或 API 检查失败，不能报告成功 |

标题状态保存在安装存储根的 `.local/titles/`，普通全局模式下即 `CODEX_HOME/agent-clarity/.local/titles/`；共享模式使用包中固定的同一个存储根。更新、卸载及标题写入使用本地锁；文件以原子替换方式写入。上次 API 写入超时后，只有回读到目标名称才确认成功，不把超时当成功，也不盲目重试。

## 更新与卸载

`update --global` 或 `update --project ...` 重新复制源码包，支持同版本内容修订和版本升级。覆盖前检查部署副本与缓存的摘要；手动修改过的内容不会自动覆盖。配置和规则只替换安装器的标记区块，其余内容保留。备份位于安装存储根的 `.local/agent-clarity/backups/`，文件权限为 0600。

`uninstall` 使用同一范围参数，先关闭标题写入，再删除托管配置和规则，并清理记录中未被修改的部署副本和插件缓存。保留用户改动、备份、已有会话名称和历史状态；独立项目安装保留。全局卸载不会重新安装曾被迁移卸载的项目插件。

`status --project ...` 查看安装记录，并实时读取本项目两个 Hooks 的启用和信任状态。`runtime_ready: true` 证明入口就绪，不能代替当前聊天实际执行证据。若复制与配置完成后插件加载或审查未完成，项目处于已配置但未就绪状态，可以修复原因后重试，或运行卸载。

## 与 Codex 的连接及限制

标题元数据调用优先使用 PATH 中的原生 `codex`，再回退到 `CODEX_CLI_PATH`；这避免 Harbor 的模型登录包装器阻止本地改名。若当前 Codex home 有控制套接字，先尝试 `app-server proxy`；否则使用 `app-server --stdio`。标题通过 `thread/read` 和 `thread/name/set` 操作，不直接修改 SQLite，也不读取或复制令牌。退出登录不删除共享安装；若没有可用模型来源，无法生成对话回合，插件也不能代替模型生成标题内容。

Codex API 没有“名称仍等于旧值才写入”的条件参数。本地锁只能协调本插件，无法锁住桌面上的手动改名，因此同时修改仍有竞争窗口。延迟到达的原生自动命名，也可能被当作外部改名而受到保护。

自动命名仍需要 Agent 执行命名指令；Hooks 用于提醒和发现漏做，不是替换模型。独立进程写入成功也不等于桌面侧栏立即刷新。若没有改名，先查真实名称、Hooks 状态和本轮核对记录，不能先归因于刷新。当前已测版本和实测结果见 [验证记录](verification.md)。

旧 `scripts/session_title.py` 仅保留兼容入口，共用插件中的实现。新安装统一使用 `scripts/title_plugin.py`，不再用旧 `activate` 或 `setup-hooks` 流程替代插件安装。
