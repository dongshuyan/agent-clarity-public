## 模型变更与评分（0.7.2）

- **故障原因。** 0.7.0 的 S2 仅从旧模型缓存中查找参考窗口。新模型已列在账户显式配置的目录里时，旧版仍可能缺少计算占用率所需的分母。0.7.2 同时覆盖了两个目录都不能提供可靠窗口的情况。[窗口来源与显示规则](session-monitor.md#实际窗口与参考窗口)
- **自动恢复。** 在安装包上重放同一会话的连续请求。模型从测试目录中移除后，标题由 `S2·32分` 变为 `S1·4分（窗口未知）`。换到尚未收录的新模型时仍能给出基础分；加入新模型的窗口后，下一轮恢复为 `S2·17分`。另一个用例在没有模型名、但有本次输入和实际窗口时直接得到完整 S2。冲突窗口、只有累计用量、严格模式缺窗口和探测失败均保留未评分。[回归用例](../tests/test_model_independent_scoring.py) · [读数测试](../tests/test_session_score.py)
- **实际安装。** macOS 上的 Codex CLI 0.169.1 在共享安装的新会话中使用 `gpt-6-luna / low`。首轮和随后的三轮续聊分别读回 S2 的 7、8、9、10 分；第五轮由同一会话模型提交自检，标题读回 `S4·11分`，其中语义增量为 0。测试后已归档该会话。三个已启用的本地配置均加载相同版本，各自七项既有 Hook 已启用且通过信任检查。
- **四档联测。** 在单独的测试项目用同一型号和 low 档完成 14 个真实回合，覆盖严格模式、S1、S2、手动标题、关闭评分以及两种语义自检。S3 第三轮读回 14 分，S4 第五轮读回 15 分。三个测试会话均已归档，测试项目的安装和临时信任已清理。[真实会话测试](../tests/live_session_scores.py)
- **开销。** 在本次机器上分别执行 20 次本地窗口查询，直接取请求字段的中位耗时小于 0.01 毫秒，从账户目录查找的中位耗时为 7.4 毫秒。测量只涵盖窗口查询。S1 会跳过该查询。
- **完整性。** 开发版与脱敏公开版各通过 211 项单元与集成回归。隔离环境另通过 22 项真实插件安装、更新和卸载检查。上述结果验证了事件采集、计分和标题持久化；分数对真实任务的预测准确率及桌面侧栏的视觉刷新尚未测量。[安装测试](../tests/live_plugin_lifecycle.py)

## 跨 Codex / Harbor 账户共享安装（0.5.0）

本次故障由本机代码和状态核对确认：Harbor 会继承所选历史位置的插件配置、规则和 Hooks 审查结果，但不会复制任意插件的私有状态。旧运行时按当前 `CODEX_HOME` 寻找启用记录，因此多个账户出现两条 Hooks 已启用且受信任、脚本却返回 `disabled` 的情况。发生这种缺失不要求用户在当前对话中手动切换账户。

共享安装现位于用户选择的稳定本地目录。包内绑定固定状态根；各账户的完整缓存副本经安装摘要核对后使用同一份状态。10 个本机配置目录已接入，包括 3 个官方账户、2 个 API 实例、1 个额外窗口及 4 个历史来源。旧全局安装停用，13 份标题保护记录保留并迁移。每个目录的最终检查只有共享插件的两条标题 Hooks 启用且为 `trusted`；其他配置经去除本插件字段后逐项比较一致。没有修改登录或模型路由。

本次用户已明确授权修复所有本机账户。部署检查了实际命令、20 秒期限、同步执行、无 matcher 和完整包摘要，再通过 Codex `/hooks` 同样使用的 `config/batchWrite` 接口写入这两条当前定义的审查摘要。没有启用全局信任跳过，也没有信任其他插件。

实际验证使用 Codex `0.163.0-alpha.10.2`、`gpt-6-luna` / `max`，启动响应的模型与档位均核对：

- 新建会话只问“请用一句中文解释什么是缓存”，模型自动维护标题。
- 通过另一官方账户正在使用的 Harbor 后端，恢复同一 ID 并追问生活例子；标题自动更新，中间的初始需求保持一致。
- 恢复修复前已经存在的旧测试会话，再问缓存到期问题；本轮自动核对通过。原来的临时工作目录按夹具记录重建，结束后清理并恢复归档。

三轮都记录到真实 `UserPromptSubmit: completed` 和 `Stop: completed`，本轮 ID、成功核对记录及原生 API 回读名称一致。没有在用户测试消息中要求改名。当前真实旧会话也已通过新运行时写入，从原生主目录和三个官方账户目录读取到同一名称。测试聊天已归档。

另在无登录文件的隔离 home 中，以原生 Codex 创建测试会话，把 `CODEX_CLI_PATH` 指向不存在的登录包装器，仍成功调用事件脚本、改名并回读；这证明本地标题功能不依赖登录桥，不代表没有模型来源时也能生成回答。首次跨账户模型测试直接启动原生后端，因该账户使用临时凭据而返回 401；改用正式 Harbor 后端后，同一会话通过，上述成功结果没有替代失败记录。

使用本机已安装 Harbor 的配置继承实现，从四个登记的历史位置分别构造新的无凭据 home。四者均由 Codex 实际发现共享 Skill 和两条受信任 Hooks，没有复制账户启用记录或认证文件。共享包使用内部磁盘，不依赖 Harbor 界面进程或源码目录继续存在；未做强制退出用户程序的测试。

122 项回归测试通过。新增测试先复现跨 home 缺失启用记录，覆盖新旧会话、每轮检查、手改保护、共享停用、损坏绑定和复制包摘要。独立代码复核发现损坏安装记录可能异常退出，已补失败回归并修复。结果见[共享版证据](portable-title-result.json)，逐轮事件、配置备份及本机路径清单保留在忽略的 `.local/account-repair-20261019/`。本次验证执行与持久化，没有做桌面侧栏视觉验收。
