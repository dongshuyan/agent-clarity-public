# 已确认的需求

- 标题采用“状态｜初始需求｜当前进展”，真实修改会话名称；初始需求稳定，保留手动修改的段。
- 表达以事实、条件、证据强度和重要信息完整为前提，降低读者寻找、理解和使用信息的成本。
- 覆盖对话、文档和学术写作；专业约束与其他领域 Skill 配合使用。
- 项目默认规则承担持续生效的部分，Skill 承担详细指导；不替换整个模型系统指令。
- 表达优化保留 Skill；标题交付为 Codex 插件，提供安装、更新、查看和卸载入口。
- 只在明确安装的测试项目和启用后新建的根会话中运行，不全局启用、不改其他项目；允许 Codex 保存正式插件缓存。
- 复用成熟方案并适当定制，不开展训练或新研究。
- 参考源码和下载资料放在被忽略的 `reference/`；运行和测试不依赖该目录。
- Agent 负责准备样本、任务、事实核对和对照评测；不要求用户寻找历史回答或参加打分。
- 对照使用相同模型、推理档位、原始材料和任务。先检查信息保真，再判断理解成本；保留未参与调整的新任务。
- 区分代码检查、模拟测试、真实 API 验证、桌面显示验证和个人阅读体验，不能互相替代。
- GitHub 仓库必须私有；上传前检查文件和敏感信息。

## 实施顺序

1. 保存并核对参考材料，记录采用与不采用的理由。
2. 编写表达规则和小规模评测材料；复用上游三段式与分段保护，实现项目内插件接入并测试边界。
3. 在新会话中验证可用部分，保留真实结果和未验证的边界。
4. 审查完整改动与上传清单，推送至私有仓库。
